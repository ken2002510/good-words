# CONTENT-GUIDE — 好話內容撰寫原則與禁用詞清單

> 適用範圍：`content/` 全部語料，以及任何由 LLM 即時生成的好話。
> 上位依據：`00-PROJECT-BRIEF.md` §3（三好四給）、§5（好話生成規則）、§6（安全護欄）。
> **本檔與 BRIEF 衝突時，以 BRIEF 為準。**

---

## 0. 一句話原則

> **先承接，再說一句真話，最後給一個今晚做得到的小步。**
> 不要安慰，要**被聽懂**。

---

## 1. 最核心的判準：「會不會讓他更孤單？」

每寫一句，問自己這一個問題：

> **「這句話，對一個真的在低潮的人說，會不會讓他更孤單？」**

會 → 重寫。

為什麼是這一句？因為空洞的正向語錄的傷害不在於「沒用」，而在於它**暗示對方的痛苦不被理解**。
當一個人說「我很累」，你回「加油」，他聽到的是「你不要講這個」。
那一刻，他會多一層孤單。

### 對照

| ❌ 讓他更孤單 | ✅ 承接 + 具體 |
|---|---|
| 加油，你可以的！ | 你已經撐了這麼久，沒有人看見，但那是真的。 |
| 別想太多，睡一覺就好了 | 明明很累，躺下來腦袋卻一直轉，那不是你的錯。 |
| 一切都會好的 | 今天不用變好，只要撐到睡覺就好。 |
| 至少你還有工作／還有家人 | 你不是不夠努力，是量本來就超過一個人。 |
| 你已經很棒了 | 事情沒做好，跟你是個不好的人，是兩件事。 |

---

## 2. 固定三段結構

每一句好話**必須**由三段組成，欄位名稱固定（builder 依此讀取）：

| 欄位 | 作用 | 寫法 | 長度 |
|---|---|---|---|
| **承接** | 把使用者的處境用自己的話說一次 | 複述**具體處境**，不是複述情緒標籤 | 1–2 句，可長 |
| **好話** | 一句真誠、具體、不空洞的話 | 短、肯定、指涉處境 | **≤ 30 字（硬上限）** |
| **小步** | 一個今晚就能做的極小行動 | 要**小到不可能失敗** | 1 句 |

### 各段的反面教材

**承接** ❌「我理解你的感受」→ 這是罐頭，不是承接。
✅「你把事情做不好，直接算成自己這個人不好。這個算法很傷，而且你已經用很久了。」
→ 關鍵：**說出他自己沒說出口的那個推論**。

**好話** ❌「你很棒，要相信自己。」
✅「你罵自己的那句話，你絕對不會對朋友說。」
→ 關鍵：**給他一個他沒想過的角度，不是給他評價**。

**小步** ❌「好好休息，對自己好一點。」
✅「今晚十一點前關燈，剩下的明天再煩惱。」
→ 關鍵：**有時間、有動作、做得到**。

## 3. 禁用詞清單（程式強制檢查）

`lint_content.py` 會掃描全部語料，命中即 **ERROR**。

### 3.1 空洞鼓勵（反毒雞湯核心禁語）

```
加油、你可以的、你一定可以、相信自己、你已經很棒了、你值得更好
別想太多、想開一點、看開一點、往好處想、要正面思考、正向思考
一切都會好的、一切都會好、明天會更好、沒事的、這沒什麼、很快就過了
時間會治癒、天無絕人之路
至少你還…、比你慘的人、知足、感恩惜福、宇宙會…
愛自己
```

> 注意：連「愛自己」也禁。它聽起來正確，但對一個正在自我厭惡的人來說，
> 那是一道**他做不到的命令**，等於再加一項失敗。

### 3.2 說教與評價語氣

```
你應該、你必須、你要學會、你該、建議你、最好的方法是
首先／其次／最後你應該、正確的做法
```

**禁止列建議清單。** 一次只給**一個**小步。
一旦出現「首先…其次…」，回應就從陪伴變成課程。

### 3.3 醫療／診斷語言

```
憂鬱症、躁鬱、恐慌症、精神疾病、心理疾病、診斷、症狀
治療、療程、服藥、用藥、處方、病理、患者、病患
```

**本作品不做診斷、不做評估、不給醫療建議。**
說「你的症狀」等於把人變成病例，也踩到專業界線。

### 3.4 AI 自稱語

```
「AI 認為」「根據分析」「我偵測到」「系統判斷」
```

直接說話，不提自己。使用者要的是有人回應，不是一份報告。

### 3.5 最重的一條：不自傷的禁止，而是安全護欄

好話語料**不得**包含任何危機處理建議。
若使用者訊息命中 `crisis.json`，**立刻中止好話流程**，走轉介（見 §6）。

## 4. 允許與鼓勵的寫法

- ✅ **承認困難是真的**：「事情永遠做不完」比「你會撐過去的」更讓人安心。
- ✅ **指出還沒被看見的力量**：「你照顧別人這麼久，也該有人問你一句。」
- ✅ **把評價還回去**：「被低估是他們看得少，不代表你做得少。」
- ✅ **具體的小到不行**：「只回一個貼圖就好」「換一條被子」。
- ✅ **留出口**：「不想講話沒關係，你不需要為休息解釋。」
- ✅ **口語、有畫面**：用「撐」「凹」「釘」「被當空氣」，不用「情緒困擾」。

## 5. 語料檔案規格

| 檔案 | 內容 | 規格 |
|---|---|---|
| `emotions.json` | 情緒分類 | 14 類；每類 `id` / `name` / `keywords[]` / `intensity[]` / `situation` / `typical_phrases[]` |
| `goodwords.json` | 好話語料庫 | 14 類 × 7 句 = **98 句**；每句 `id` / `承接` / `好話` / `小步` |
| `crisis.json` | 危機詞庫 | 10 個 pattern 群組，變體總數 >100；含 `severity_rules` 與 `negative_guard` |
| `share_templates.json` | 好話轉送模板 | 朋友／家人／同事 × 各 3 種語氣，另 2 個通用模板 + `sender_notes` |
| `lint_content.py` | 品質關卡 | 禁用詞 + 結構 + BOM 檢查，`--strict` 可作 CI |

**編碼硬要求：UTF-8 無 BOM。**（隊友踩過 BOM 的坑；`lint_content.py` 會逐檔檢查。）

### 情緒 id 一覽（builder 對照用，不得更名）

`self_negation`（自我否定）、`work_stress`（工作壓力）、`heartbreak`（感情失落）、
`family_conflict`（家庭衝突）、`loneliness`（孤獨）、`anxiety`（焦慮）、
`guilt`（內疚）、`exhaustion`（疲憊）、`misunderstood`（被誤解）、
`future_loss`（未來迷惘）、`being_ignored`（被忽略）、`anger_helpless`（憤怒與無力）、
`failure_setback`（挫敗與失去）、`people_pleasing`（討好與界線）

## 6. 危機處理（不可省略，優先於一切）

觸發 `crisis.json` 即**停止一般回應**，改走：

1. 開場：「你願意把這件事說出來，這很重要。」
2. 明確說出「我沒辦法取代真正能幫你的人」
3. 顯示真實資源：**1925 安心專線／1995 生命線／1980 張老師**（有立即危險時 119、110）
4. 語氣不恐慌、不說教、不扮演諮商師

**誤判處理原則：寧可多轉介一次，也不可漏接。**
`negative_guard` 已列出「笑死」「累死」「想死你了」等口語例外。

## 7. 三好四給對照（給說明書引用）

| 精神 | 內容層怎麼落地 |
|---|---|
| 說好話 | 98 句語料，全部通過「不空洞」檢查；LLM 生成時作為 few-shot 品質下限 |
| 做好事 | `share_templates.json`：一鍵生成給朋友／家人／同事的轉送版本 |
| 存好心 | 全語料零評價、零診斷、零建議清單；`lint_content.py` 強制 |
| 給人信心 | 好話段聚焦「你已經做到了什麼」 |
| 給人歡喜 | 口語、有畫面感的句子（「撐」「凹」「被當空氣」） |
| 給人希望 | 每句都有 `小步`，是今晚做得到的極小行動 |
| 給人方便 | 純 JSON、零依賴、免登入，前端直接 fetch |

---

## 8. 修改流程

1. 改 `content/` 任一 JSON
2. 跑 `python lint_content.py --strict`
3. **ERROR 不為 0 不得交付**
4. LLM 即時生成的句子，伺服器端應套用同一份禁用詞表做後置過濾
